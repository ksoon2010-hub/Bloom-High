# Bloom High — 센터 유지율 현황

회원 이름과 상태를 월별로 기록하고 활동 인원, 유지율, 유지 개월 수를 확인하는 웹앱입니다.

## 사용 방법

현재 앱은 Supabase 이메일·비밀번호 로그인 후 지정 센터의 접근 권한을 확인합니다. 기존 Auth 계정을 사용하며 가입 기능은 없습니다. `public.bloom_high_centers`의 `id`만 조회하고 기존 SELECT RLS 정책이 허용한 행이 있을 때 회원 화면을 엽니다. 비공개 스키마와 Supabase 회원 기록 테이블은 사용하지 않습니다.

### 로그인 설정과 로컬 실행

Node.js 24와 pnpm을 사용합니다. 프로젝트 루트의 Git 제외 파일 `.env.local`에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 설정하세요. URL은 이 프로젝트의 Supabase URL이며 키는 publishable 또는 기존 anon key만 허용됩니다. service_role·secret key는 빌드에서 거부합니다. 키나 비밀번호를 로그·문서에 붙여 넣지 마세요.

`pnpm install` 후 `pnpm dev`로 로컬 서버를 시작하거나 `pnpm build`로 Pages용 assets를 갱신합니다. 빌드는 두 공개 설정만 포함하며 `.env.local` 자체를 게시하지 않습니다. 환경변수도 지원하며 파일보다 우선합니다. 설정을 바꾸면 개발 서버를 재시작하세요. 로그인은 동일 페이지에서 표시하므로 Pages의 기존 상대 경로를 유지합니다. HTTPS를 사용하세요. 이메일 링크·비밀번호 재설정은 이번 범위에 포함되지 않습니다.

Supabase 인증 세션은 `bloom-high-auth-v1`에 별도로 저장됩니다. 로그인·로그아웃은 기존 `bloom-members-v1` 기록을 변경하거나 삭제하지 않습니다. 로그아웃은 현재 브라우저의 세션에만 적용됩니다. 회원 기록은 여전히 브라우저에 있으며 계정·센터별 분리나 서버 이전을 하지 않습니다. 공용 브라우저에서 개발자 도구로 로컬 기록을 읽는 것은 로그인 화면으로 막을 수 없습니다.

`pnpm test`와 `pnpm typecheck`로 기본 검증을 수행합니다. 인증 테스트는 가상 계정과 모의 응답만 사용합니다. 실제 RLS 검증은 별도 브라우저에서 허용 계정·권한 없는 계정으로 로그인하고, 새로고침·만료·로그아웃·통신 실패를 확인하세요. 회원 데이터에 대한 요청은 없어야 하며 센터 조회는 해당 ID의 GET 요청만 있어야 합니다. 기존 회원 저장값은 로그인 전후 동일해야 합니다. 현재 자동 테스트는 실제 Supabase 계정이나 DB를 변경하지 않습니다.

1. `index.html`을 더블 클릭해 브라우저에서 엽니다.
2. 기준 월을 선택하고 **회원 추가**로 이름과 상태를 입력합니다.
3. 이름 검색, 수정·삭제, **지난달 회원 가져오기**를 사용할 수 있습니다.
4. **엑셀용 내려받기**로 선택한 달의 목록을 CSV 파일로 저장합니다.

기록은 서버로 보내지 않고 현재 브라우저의 **localStorage**에 저장합니다. 다른 컴퓨터·브라우저와 자동으로 공유되지 않고, 브라우저 데이터를 지우면 기록도 삭제됩니다. CSV는 선택한 달의 목록이며 전체 기록 복원용 백업은 아닙니다. 처음에는 빈 목록으로 시작합니다.

## GitHub Pages에 올리기

이 폴더 내용을 GitHub 저장소에 올립니다. 저장소의 **Settings → Pages**에서 **Deploy from a branch**, 올린 브랜치(보통 `main`), **/(root)**를 선택하고 **Save**를 누릅니다.

`index.html`, `assets`, `public`, 빈 `.nojekyll` 파일을 꼭 포함하세요. 완성된 화면 파일이 들어 있어 별도 빌드 없이 게시할 수 있습니다. 파일 경로는 상대 경로입니다.

사이트와 저장소 파일은 누구나 볼 수 있습니다. 실제 회원 자료를 코드 파일에 넣어 올리지 마세요. 앱에서 입력한 기록은 브라우저에만 남지만, 공용 컴퓨터에서 같은 브라우저를 사용하는 사람은 볼 수 있습니다.

## 폴더 구성

- `index.html`: 첫 화면
- `assets`: 실제 실행되는 완성된 JS·CSS
- `public`: 아이콘
- `app`, `lib`: 원본 화면과 기능 코드
- `scripts`, `tests`: 빌드·기능 확인 도구

원본을 수정할 경우 Node.js와 pnpm을 설치하고 `pnpm install`, `pnpm run build`를 실행해 `assets`도 다시 만들어 올리세요. `pnpm test`는 핵심 기능을 검사합니다. 기존 서버·UI 원본 일부는 보존되어 있지만 정적 앱에서는 사용하지 않습니다.

## 중단 회원 조회

‘중단 회원’ 메뉴에서 월별 보기(연도·월 선택)와 전체 보기를 전환합니다. 이름 옆 숫자는 신규 등록월부터 중단월까지 포함한 개월 수입니다. 신규 기록이 없으면 등록월·개월 수는 알 수 없음으로 표시합니다. 중단 기록은 삭제할 수 없으며 기존 통계 계산은 그대로입니다.

## CSV 회원 가져오기

회원 현황에서 ‘CSV 파일 가져오기’를 눌러 Sites에서 받은 CSV를 선택합니다. 기준 월·회원 이름·상태·유지 개월을 읽어 미리 보기와 건수를 표시합니다. 중복은 같은 월과 이름으로 확인하고 기본적으로 건너뛰며, 확인한 경우에만 별도 회원으로 추가합니다. 기존 기록은 덮어쓰지 않습니다. 다른 월의 동명 회원은 자동 연결하지 않습니다. CSV 파일과 이름은 서버로 전송하지 않으며 현재 브라우저에만 저장됩니다. 인터넷 사이트와 개발 서버의 저장소는 서로 다르므로 사용할 사이트에서 가져오세요.

## 2・4・7・13개월 유지율 분석

‘유지율 분석’ 메뉴에서 기준 연도·월과 신규 회원 / 전체 회원을 선택합니다. 신규는 기준 월의 ‘신규’ 회원, 전체는 기준 월의 활동 회원(유지·신규·전입)을 고정된 분모로 사용합니다. 등록월 또는 기준 월을 1개월째로 계산하여 목표 월은 각각 1·3·6·12개월 후입니다. 이후 가입한 회원은 대상에 추가하지 않습니다.

매달 같은 회원 ID의 활동 기록을 확인하며, 중단·전출은 해당 이력의 종료로 집계합니다. 이후 신규·전입 기록은 별도 이력이므로 이전 기준 월의 유지로 계산하지 않습니다. 명시적인 중단·전출 이후 기록은 필요하지 않지만 목표 월의 기록은 있어야 합니다. 필요한 기록이 없거나 같은 ID의 월별 기록이 중복되면 ‘데이터 부족’으로 표시하고 비율은 계산하지 않습니다. 미래 목표 월은 ‘집계 대기’입니다.

카드를 누르면 유지 회원, 중단·전출 회원, 확인 필요, 집계 대기 명단을 볼 수 있습니다. 등록월은 신규 기록으로만 확인하며 유지 개월 수에서 역산하지 않습니다. 전체 회원은 등록월이 없어도 기준 월부터 분석합니다. 이름만 같은 별도 ID는 서로 연결하지 않습니다.

분석은 기존 `bloom-members-v1` 기록을 읽기만 하며 저장 구조를 변경하지 않습니다. 기존 월별 유지율 공식, CSV 가져오기와 중단 회원 기록은 유지됩니다. 전출은 이번 분석에서 고정 분모에 남고 유지 인원에서 제외됩니다. 테스트는 가상 회원만 사용합니다.

## 전체 데이터 백업·복원

모든 메뉴 아래의 ‘전체 데이터 백업’ 버튼으로 `bloom-high-backup-YYYY-MM-DD.json`을 다운로드합니다. 날짜는 한국 시간 기준입니다. 모든 월별 원본 기록, 회원 ID, 상태, 메모와 직접 입력한 유지 개월 수를 보관하므로 신규 등록월 및 중단·재등록 이력을 동일하게 복원합니다. 등록월이나 자동 유지 개월 수는 기존 기록에서 계산하며 추정한 값을 새로 저장하지 않습니다.

‘데이터 복원’에서 이 앱으로 만든 JSON 백업을 선택하면 고유 회원 ID 기준 회원 수, 전체 월별 기록 수와 월별 건수를 미리 표시합니다. 기존 기록은 병합하지 않고 백업 내용으로 전부 교체하므로 기존 기록이 있으면 경고하고, 마지막 확인 창에서도 동의를 받습니다. ‘복원 전 현재 데이터 자동 백업’은 기존 기록이 있으면 기본 선택되며 덮어쓰기 전에 `bloom-high-before-restore-backup-YYYY-MM-DD.json`을 다운로드합니다. 브라우저의 다운로드 폴더에서 파일을 확인하세요.

파일 형식·버전·전체 회원 기록·중복 기록 ID와 SHA-256 체크섬을 검사합니다. 잘못되거나 변조·손상된 파일은 저장하지 않습니다. 20MB까지 선택할 수 있으며 미리 보기 이후 현재 기록이 바뀌면 복원을 중단합니다. 빈 백업 복원은 모든 기록을 지우므로 별도 경고합니다. 복원은 기존 `bloom-members-v1` 키에 한 번에 저장하며 새로고침 후에도 유지됩니다.

파일 선택·검증·다운로드·복원 과정에서 회원 정보를 외부 서버로 보내지 않습니다. JSON에는 회원 정보가 있으므로 공개 저장소에 올리지 마세요. 기본 백업 파일명 패턴은 `.gitignore`에서 제외하며 개발 테스트는 가상 데이터만 사용합니다.
